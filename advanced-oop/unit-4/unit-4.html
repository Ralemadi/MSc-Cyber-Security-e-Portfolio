Unit 4: Design Patterns II - Structural Patterns

Advanced Object-Oriented Design and Programming

Unit Overview

During this unit, I explored structural design patterns and how they organise classes and objects into larger and more flexible structures. The unit covered Adapter, Bridge, Composite, Decorator, Facade, Proxy and Flyweight. The unit also included a seminar exercise on the Decorator Pattern, which I completed independently using a coffee-shop example. The exercise demonstrated how additional features can be added dynamically without modifying the original object, while the collaborative discussion involved applying Adapter, Bridge and Composite through Python-based cybersecurity scenarios.

Learning Outcomes

After completing this unit, I was able to:

  • Understand the purpose of structural design patterns in object-oriented software
  • Recognise the seven main structural patterns and the different design problems they address.
  • Explain how structural patterns can improve modularity, flexibility and maintainability.
  • Apply Adapter, Bridge, Composite and Decorator patterns through practical Python examples.
  • Recognise that a design pattern should be selected according to the problem rather than used unnecessarily.
  • Recognise how good software design can improve maintainability, flexibility, scalability and reliability.

Artefacts and Practical Exercises

The main artefact for this unit was Collaborative Discussion 1. For the Adapter Pattern, I developed a security log collection example in which a legacy collector used the old method, while a modern collector used the standard method. I used the Adapter Pattern to convert the legacy records into the same structured format as the modern events, allowing both sources to be accessed through one interface and combined into a single event list.

For the Bridge Pattern, I explored how different parts of a system can be separated so they can change independently without creating unnecessary class combinations. For the Composite Pattern, I applied a common interface to individual objects and groups, allowing them to be organised and handled consistently within a hierarchical structure.

As part of the seminar exercise, I implemented the Decorator Pattern through a coffee-shop application to understand how new functionality can be added to an object without modifying its original structure. The exercise demonstrated how behaviour can be extended dynamically and flexibly, helping to reduce unnecessary changes to existing code and improve maintainability.

Reflection

This unit extended my understanding of design patterns from Unit 3. Creational patterns focused mainly on how objects are created, whereas structural patterns helped me think about how existing classes and objects can be connected and organised.

I found the security-based examples particularly useful because they demonstrated how the same design principles can be applied to realistic cybersecurity scenarios. Implementing the different patterns helped me distinguish more clearly between integration problems, separation of responsibilities and hierarchical organisation. The exercises also reinforced that introducing a design pattern adds structure to a program and should therefore be justified by a clear design problem rather than used unnecessarily.

As part of the Collaborative Discussion, I also responded to a challenging question raised under Seba’s Adapter Pattern post. The question encouraged me to think more critically about whether the additional code introduced by the Adapter Pattern necessarily increases system complexity. I reviewed two supporting sources to support my response and concluded that the additional code does not necessarily make the system more complex if the adapter is kept simple and the integration logic is clearly separated. My research also helped me distinguish between object and class adapters. An object adapter uses composition, while a class adapter relies on inheritance (Gamma et al., 1994; Sarcar, 2022). Based on this, I concluded that the object adapter approach can provide greater flexibility when integrating different service implementations. This activity encouraged me to go beyond the initial implementation, research the design choices more deeply and support my response with evidence.

Professional Skills Development and Action Plan

The practical work in this unit developed my ability to identify structural design problems and select patterns that suit different system requirements. Applying Adapter, Bridge and Composite to cybersecurity scenarios was particularly relevant because integration between different technologies, legacy systems, communication methods and complex system structures is common in digital environments.

In future work, I plan to consider these patterns when addressing similar design requirements, while evaluating whether the additional structure genuinely improves system integration, flexibility and maintainability. I also aim to think beyond the immediate implementation by considering different possible scenarios and design challenges, similar to the questions raised during the Collaborative Discussion. This will help me evaluate design choices from different perspectives rather than relying only on the most obvious solution.
