# Audit Folder

This folder stores the security and operational audit trail generated by
BankSecure.

The audit log is separate from the main SQLite banking database so that
operational records and audit evidence have clearly separated responsibilities.

## Main File

```text
audit.jsonl
```

The file uses JSON Lines format.

Each line is one independent JSON audit event.

Example structure:

```json
{
  "timestamp": "2026-09-27T19:30:00+00:00",
  "actor": "admin",
  "action": "UNLOCK_USER",
  "outcome": "COMPLETED",
  "details": {
    "username": "user1",
    "failed_attempts": 0
  }
}
```

Actual values depend on the operation performed.

## What Is Recorded

The audit trail can contain events related to:

- Login success
- Failed login attempts
- Temporary login lockout
- Temporary lockout expiry
- Administrator unlock
- User creation
- Customer creation
- User enable and disable actions
- Role changes
- Password-change and password-reset actions
- Account-status changes
- Deposits
- Withdrawals
- Transfers
- Fraud and risk information used internally by transfer processing

## Authentication Events

Important authentication actions include:

```text
LOGIN_FAILED
LOGIN_SUCCESS
TEMPORARY_LOCKOUT
TEMPORARY_LOCKOUT_EXPIRED
UNLOCK_USER
```

A user is temporarily locked after five consecutive failed login attempts.

The temporary lock lasts five minutes unless an authorised Administrator clears
it earlier.

## Security Rules

Passwords must never be written to the audit log.

The audit log can contain security metadata needed for traceability, but normal
customer-facing messages must not expose internal fraud scores or risk details.

## Relationship with the Database

```text
db/banksecure.db
= Operational banking and user data

audit/audit.jsonl
= Audit and security event history
```

The two files serve different purposes.

## Reading the Audit Log

PowerShell:

```powershell
Get-Content audit\audit.jsonl
```

Search for authentication-security events:

```powershell
Select-String -Path audit\audit.jsonl -Pattern "LOGIN_FAILED|TEMPORARY_LOCKOUT|LOGIN_SUCCESS|UNLOCK_USER"
```

Linux / macOS:

```bash
cat audit/audit.jsonl
```

or:

```bash
grep -E "LOGIN_FAILED|TEMPORARY_LOCKOUT|LOGIN_SUCCESS|UNLOCK_USER" audit/audit.jsonl
```

## Implementation

Audit writing and reading are implemented mainly in:

```text
banking/services/audit_service.py
banking/services/audit_details.py
```

Transfer auditing is also connected through:

```text
banking/patterns/decorators.py
```

The Administrator can review authorised audit information through the
`Administration & Audit` workflow.
