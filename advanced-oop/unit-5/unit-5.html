Unit 5: Design Patterns III - Behavioural Patterns

Advanced Object-Oriented Design and Programming

Unit Summary

During this unit, I explored behavioural design patterns and how they define the way objects interact, communicate and share responsibilities within object-oriented software. Gamma et al. (1994) describe behavioural patterns as patterns concerned with algorithms and the assignment of responsibilities between objects. The unit covered Strategy, Observer, Chain of Responsibility, Template Method, Command and State, with the practical work focusing on the application of the Strategy Pattern.

Learning Outcomes

After completing this unit, I was able to:

  • Understand the purpose of behavioural design patterns in object-oriented software.
  • Recognise the six behavioural patterns and the different interaction problems they address.
  • Explain how behavioural patterns can improve flexibility, communication and maintainability.
  • Apply the Strategy Pattern in a practical Python refactoring exercise.
  • Recognise how behavioural patterns can be applied to software and cybersecurity scenarios.

Artefacts and Practical Exercises

The main artefact for this unit was Collaborative Discussion 2, which involved analysing and refactoring a simple payment processing system using the Strategy Pattern. The original implementation used an if/elif structure to select payment methods, which created tight coupling and required the existing PaymentProcessor class to be modified whenever a new payment option was introduced.

I refactored the design by defining a common payment strategy interface and separating each payment method into its own strategy class. Sarcar (2022) explains that the Strategy Pattern separates alternative behaviours into interchangeable strategy implementations. PaymentProcessor then delegated the payment operation to the selected strategy, allowing the behaviour to be changed without modifying the processor itself. This exercise demonstrated how the Strategy Pattern can support the Open/Closed Principle while improving extensibility and testability.

Unit 5 Reflection

This unit helped me understand that design patterns are not limited to object creation or class structure. Behavioural patterns focus on how responsibilities and actions are distributed between objects. The Strategy exercise was particularly useful because it demonstrated how a growing conditional structure can be replaced with interchangeable behaviours through a common interface.

The exercise also reinforced my understanding of the Open/Closed Principle from the earlier SOLID unit. New payment behaviours could be introduced without modifying the main processor. At the same time, I recognised that design patterns can introduce additional structure and classes, so they should be applied when the expected flexibility and maintainability justify this additional complexity.

Since the unit materials mentioned the Observer Pattern in cybersecurity systems, I explored the topic independently. Hurst, Merabti and Fergus (2014) demonstrate how observers can be used to monitor system behaviour and support the identification of cyber threats through changes in system activity. This helped me understand how changes in a monitored state can trigger alerts and allow immediate response actions to follow. Together, these lessons improved my confidence in designing maintainable and adaptable systems.

Professional Skills Development and Action Plan

The work in this unit improved my ability to identify behaviour that may change and separate it from stable application logic. It also strengthened my understanding of how object-oriented design can support software that is easier to test, extend and maintain.

In future security-related development, I intend to consider behavioural patterns when designing components such as alert handling, monitoring workflows and response actions. I will focus on selecting a pattern based on a clear design problem rather than introducing additional structure unnecessarily.
