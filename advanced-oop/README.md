# Module Reflection

Across Units, my understanding progressed from individual OOP concepts to broader software-design decisions.

**Unit 1** established the foundation by revisiting inheritance, polymorphism, abstraction and encapsulation.  

**Unit 2** moved from individual programming concepts to design quality through SOLID principles.  

**Unit 3** introduced creational patterns and demonstrated how object creation can be separated from application logic.  

**Unit 4** shifted the focus to structural relationships between objects and classes.  

**Unit 5** then explored how responsibilities and behaviour can be distributed between interacting objects.

A recurring theme across the module has been the importance of designing software that is not only functional but also **maintainable, extensible and understandable**.

The practical exercises also helped me relate object-oriented design to cybersecurity. Examples involving controlled access to state, legacy log integration, security alert delivery, asset hierarchies and behavioural monitoring demonstrated how design principles can be applied to security-related systems.

Another important lesson has been that abstraction, SOLID principles and design patterns should not be applied unnecessarily. Additional classes and interfaces create value when they solve a clear design problem, reduce coupling or support expected change. This has encouraged me to evaluate design choices based on context rather than applying patterns mechanically.

Going forward, I intend to continue applying these principles when developing security tools, automation scripts, monitoring components and other software where maintainability and controlled system behaviour are important.
