Unit 2: SOLID Principles of Object-Oriented Design

Advanced Object-Oriented Design and Programming

Unit Overview

Unit 2 focused on the SOLID principles and how they can be used to improve the structure of object-oriented software. These five principles provide practical guidance for designing software that is easier to understand, maintain, extend and adapt.

The practical exercise involved reviewing a poorly designed online shopping system and refactoring it using SOLID principles. This helped demonstrate how separating responsibilities, reducing unnecessary dependencies and using abstractions can improve software design and make future changes easier to manage.

Learning Outcomes

After completing this unit, I was able to:

  • Understand the purpose of the five SOLID principles.
  • Apply SOLID principles when refactoring object-oriented code.
  • Understand how abstractions can reduce dependencies between software components.
  • Recognise how good software design can improve maintainability, flexibility, scalability and reliability.
  • Understand how encapsulation and abstraction can support controlled access to data.

Artefacts and Practical Exercises

The practical exercise involved refactoring a poorly designed online shopping system. The code was reviewed and restructured by separating responsibilities, reducing direct dependencies and improving the interaction between different components.

The exercise provided practical experience in applying SOLID principles to an existing software design and demonstrated how refactoring can improve the overall structure of the code.

Reflection

Unit 2 helped me understand why software design becomes more important as applications grow in size and complexity. Since my previous programming experience mainly involved smaller programs, issues such as class responsibilities and dependencies were less noticeable. This became more relevant when considering larger systems such as banking, healthcare and government platforms, where poor design can make maintenance and future changes more difficult, increasing the risk of errors, security weaknesses and service disruption.

Professional Skills Development and Action Plan

The refactoring exercise helped me develop a more structured approach to reviewing existing code before making changes. I learned to identify design issues such as mixed responsibilities and tight dependencies and consider how changes to one component may affect other parts of the system. This will help me take a more systematic approach when reviewing and modifying larger software systems.
